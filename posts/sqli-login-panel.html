Union-Based SQL Injection: From Login Panel to Full DB Access

A real-world SQLi finding — how I identified it, confirmed it, and demonstrated full database read/write/drop impact during a client engagement.

Details anonymised per responsible disclosure agreement.

// initial recon

During a web application assessment, I noticed the login panel was passing user-supplied input directly into what appeared to be a raw SQL query. A single quote in the username field returned a database error — a classic early indicator.

' OR '1'='1
-- Response: You have an error in your SQL syntax...

// confirming injectable parameter

I used order-based detection to confirm the number of columns being returned, then moved to a UNION SELECT approach to extract data from other tables.

' ORDER BY 3--
' UNION SELECT NULL,NULL,NULL--

// extraction with sqlmap

After manual confirmation, I ran SQLMap to enumerate the database schema and demonstrate the full impact — including table enumeration, user credential extraction, and the ability to perform DROP and CREATE operations.

sqlmap -u "https://target.io/login" \
  --data="user=test&pass=test" \
  --dbs --batch --level=3

// impact and remediation

The vulnerability exposed the entire database, including customer PII and hashed credentials. Recommended fixes: parameterised queries (prepared statements), input validation, and least-privilege database accounts.
